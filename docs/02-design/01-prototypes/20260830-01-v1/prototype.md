## จุดที่เน้นตาม NFR/หลักการออกแบบ (ตรวจสอบตัวเองแล้ว)

- **ตัวเลือกระดับความเสียหาย 3 สี** (`field-survey-summary.html`, `lead-review-detail.html`) — ไอคอนรูปทรงต่างกัน (วงกลม/สามเหลี่ยม/แปดเหลี่ยม) + ข้อความไทย + สีครบ ไม่มีตัวเลือกใดถูกเลือกไว้ล่วงหน้า (UX-02, DESIGN.md §3.4)
- **การ์ดผลวิเคราะห์ AI** (`field-survey-photo-ai.html`) — ขอบประ + ป้าย "AI เสนอ — รอการยืนยัน" + ปุ่มสามทาง (ยืนยัน/แก้ไข/กรอกเอง) ทุกปุ่มใช้คลาส `.btn-secondary`/`.btn-primary` ขนาดเท่ากันทั้งหมด (`.btn-field` height 56px เต็มความกว้าง) ตามข้อกำหนด UX-08 ว่ากรอกเองต้องมีน้ำหนักเท่าเส้นทาง AI — มีปุ่มจำลองสถานการณ์ (JS แบบ vanilla ไม่พึ่ง CDN) ให้กดดูได้ทั้งเส้นทาง AI สำเร็จ/ไม่สำเร็จ/กรอกเองตั้งแต่ต้น
- **ตัวบ่งชี้สถานะซิงค์** ปรากฏ sticky อยู่บนทุกหน้าจอภาคสนาม (`field-survey-*.html`) ใช้ `.sync-indicator.offline` ซึ่งใช้โทน `--state-offline-*` (ไม่ใช่สีแดง/ไอคอนเตือนภัย) ตาม UX-07
- **พื้นที่กด** — ปุ่ม/ช่องกรอกบนหน้าจอภาคสนามทั้งหมดใช้คลาส `.btn-field`/`.input` สูง `--touch-field` (56px) ตัวเลือกระดับความเสียหายและปุ่มยืนยันผล AI ใช้ `--touch-critical` (64px) ผ่านคลาส `.severity-option`/`.ai-card .btn`
- **ตัวอักษรภาคสนาม** — `body` ใช้ `--text-base` 17px / `--leading-normal` 1.70 เป็นค่าเริ่มต้นของ `:root` หน้าจอ back-office (`.layout-office`) override เป็นสเกลเดสก์ท็อปตาม DESIGN.md §2.5
- **Dashboard** (`dashboard.html`) ใช้เฉพาะสีสถานะความเสียหาย (เขียว/เหลือง/แดง) ที่ผูกความหมายตายตัวอยู่แล้วใน DESIGN.md §2.3 เป็นสีของ stacked bar (ไม่ใช่จานสี categorical ใหม่) มี legend + ตารางข้อมูลสำรองสำหรับการเข้าถึง (ปรึกษา skill `dataviz` ก่อนออกแบบหน้านี้)
- **Manual Conflict Resolution** (`conflict-list.html`, `conflict-detail.html`) จำกัดการเข้าถึงไว้เฉพาะหัวหน้าผู้สำรวจ/ผู้ดูแลระบบตาม spec — ไม่มีลิงก์เข้าถึงจากหน้าจอผู้สำรวจภาคสนามหรือหน่วยงานส่วนกลาง ใช้ two-column comparison + `--font-mono` สำหรับค่าที่ต้องเทียบตัวต่อตัว + ไฮไลต์เฉพาะ field ที่ต่างกันด้วย `--state-conflict-bg` ตาม DESIGN.md §3.7
- **การกระทำที่ย้อนกลับไม่ได้** (ส่งผลสำรวจ, ลงลายเซ็น, ปลดสถานะขัดแย้ง) ทุกจุดมี dialog สรุปผลลัพธ์ก่อนยืนยันตาม UX-09
- **การปิดการใช้งานบัญชี** (`admin-users.html`) **ย้อนกลับได้** โดยเปิดใช้งานบัญชีคืนภายหลัง (ตรงกับ operation 2.4 "เปิดใช้งานบัญชีผู้ใช้คืน" ใน [[api-spec#2.4 เปิดใช้งานบัญชีผู้ใช้คืน|api-spec.md]]) — dialog ยืนยันจึงยังคงเป็น `.btn-destructive` (เพราะกระทบสิทธิ์การเข้าถึงทันที) แต่ไม่นับรวมอยู่ในหมวดย้อนกลับไม่ได้ข้างต้น (แก้ไขจากการตรวจพบโดย `/audit-prototype` ว่าข้อความ dialog เดิม "ย้อนกลับได้โดยเปิดใช้งานใหม่ภายหลัง" ขัดกับการจัดหมวดในเอกสารนี้ก่อนหน้า)
- **negative case ของการเข้าสู่ระบบ** (`login.html`) เพิ่มปุ่มสาธิต 3 สถานการณ์ตามรูปแบบเดียวกับ `field-survey-photo-ai.html` (toggle panel ด้วย vanilla JS): ข้อมูลเข้าสู่ระบบไม่ถูกต้อง (FR-25 AC-2 · TC-14-02, ใช้ `.field-error`/`.input.error`), ไม่มีสิทธิ์เข้าถึงหน้าจอนอกบทบาท (FR-26 AC-2 · TC-14-05, ใช้ `.banner.danger` — ส่วนขยายใหม่ของ `.banner` ใน `style.css` ประกอบจากโทเค็น `--severity-danger-*` เดิม ตามรูปแบบเดียวกับ `.banner.offline`/`.conflict`/`.info` ที่มีอยู่แล้ว), credential ที่แคชไว้ออฟไลน์หมดอายุ (NFR-09 AC-1 · TC-14-07/08, ใช้ `.banner.danger` เช่นกัน)
- **empty state ของ Dashboard** (`dashboard.html`) เพิ่มการ์ดสาธิตพื้นที่ที่ยังไม่มีอาคารถูกสำรวจ (FR-22 AC-2) ใช้คลาส `.empty-state` เดิมใน `style.css` ตรงตามกติกา DESIGN.md §3.9 ที่ต้องอธิบายทั้งสาเหตุและสิ่งที่ควรทำต่อ ไม่ใช่แค่คำว่า "ไม่มีข้อมูล" — เป็นการ์ดสาธิตแยกต่างหาก ไม่ใช่การกรองข้อมูลจริง (ตอนนี้ลิงก์เชื่อมไปยัง `lead-assign.html` แล้ว เพราะฟีเจอร์ 8 อยู่ในขอบเขตแล้ว)
- **การมอบหมายงาน (FR-20, ฟีเจอร์ 8)** แยกเป็น 2 หน้าจอตามบทบาทและมุมมองในคนละ journey ตาม `user-journey.md`: `lead-assign.html` (หัวหน้าผู้สำรวจสร้าง/มอบหมาย) และ `field-my-tasks.html` (ผู้สำรวจภาคสนามรับและเริ่มสำรวจ) ทั้งสองหน้าใช้ข้อมูลตัวอย่างชุดเดียวกัน (อาคาร 3 รายการ) เพื่อให้เห็นความต่อเนื่องของ journey เดียวกันจากสองมุมมอง — การเพิ่มฟีเจอร์นี้ทำให้ต้องเติมขั้นตอน "รับมอบหมายงาน" กลับเข้า journey ภาคสนาม (แก้ไข `login.html` demo-role/go-btn default target และเพิ่มลิงก์ใน `field-survey-building.html`)
- **วาดภาพประกอบเพิ่มเติม** (`field-survey-sketch.html`, FR-15) วางเป็นขั้นตอนเสริมไม่บังคับระหว่าง `field-survey-photo-ai.html` กับ `field-survey-summary.html` ตรงกับ decision node ใน `user-journey.md` — ใช้คลาส `.signature-pad` เดิม (dashed touch-input box) แทนการสร้าง component ใหม่สำหรับพื้นที่วาดภาพ เพราะเป็น component รูปแบบ "พื้นที่รับ touch-input สำหรับวาด/เขียน" ที่ใกล้เคียงที่สุดที่มีอยู่แล้วใน `style.css`
- **ค้นหา/กรอง + ส่งออกรายงาน** (`building-search.html`, FR-23/FR-24/NFR-10) — รวม 2 ฟีเจอร์ไว้หน้าเดียวเพราะ `user-journey.md` ของหน่วยงานส่วนกลาง/ผู้บริหารเดินจากกรองผลลัพธ์ไปสู่ส่งออกผลลัพธ์ชุดเดียวกันต่อเนื่อง ใช้ปุ่มสาธิตสลับมุมมองบทบาท (`.role-panel`, รูปแบบเดียวกับ `.path-panel` ใน `login.html`/`field-survey-photo-ai.html`) เพื่อแสดงว่าหัวหน้าผู้สำรวจเห็นเฉพาะส่วนค้นหา/กรอง ส่วนหน่วยงานส่วนกลาง/ผู้บริหารเห็นปุ่มส่งออกเพิ่มด้วยตามข้อสมมติในหัวข้อ 2 ของ "ข้อสมมติ/ประเด็นค้างพิจารณา" ของ `user-journey.md` — banner แจ้งจำนวนระเบียนที่ถูกซ่อนเพราะรอแก้ไขความขัดแย้ง (NFR-10) ปรากฏเหนือผลการค้นหาเสมอ ไม่ว่าจะสลับมุมมองบทบาทใด
