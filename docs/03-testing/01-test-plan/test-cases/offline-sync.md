# Test Case: การทำงานออฟไลน์และซิงค์ข้อมูลภาคสนาม

อ้างอิง: [[feature-list#13. การทำงานออฟไลน์และซิงค์ข้อมูลภาคสนาม|ฟีเจอร์ 13]] · [[user-journey#Journey: ผู้สำรวจภาคสนามลงพื้นที่สำรวจอาคาร|journey ผู้สำรวจภาคสนาม]] ขั้นตอน 8, 27 (ปรับเลขขั้นตอน 2026-09-03 ตาม journey ที่ขยายจาก 22→27 ขั้นตอนหลังแยกขั้นตอนเข้าสู่ระบบเป็น 6 ขั้นตอนย่อย) · [[acceptance-criteria#13. การทำงานออฟไลน์และซิงค์ข้อมูลภาคสนาม|acceptance-criteria]]

ฟีเจอร์นี้เป็นความเสี่ยงเฉพาะของระบบ (offline-first และการ sync) — ให้ความสำคัญเป็นพิเศษกับความสมบูรณ์ของข้อมูลเมื่อกลับมามีสัญญาณ

หมายเหตุอัปเดต (2026-09-03): ผู้ใช้ปิดข้อสมมติจำนวนภาพสูงสุด = **5 ภาพต่อบริเวณ** ([[acceptance-criteria#FR-12 (สูง) — ถ่ายภาพประกอบความเสียหายผูกกับตำแหน่ง/บริเวณ\|FR-12 AC-3]]) ใช้ค่านี้ประมาณปริมาณไฟล์ภาพสูงสุดต่ออาคารเมื่อออกแบบ test data ของ TC-13-02/TC-13-03/TC-13-06 ด้านล่าง (ไม่มี AC ใหม่เพิ่มในฟีเจอร์นี้จากรอบนี้ เพราะพฤติกรรมการซิงค์/บีบอัด/resume ที่ทดสอบอยู่แล้วไม่เปลี่ยนแปลง)

หมายเหตุ (ปรับปรุง 2026-09-02): TC-13-08/TC-13-09 ด้านล่างมีขั้นตอน "เปิดดูประวัติ (audit trail) ของอาคารนั้น" ซึ่งขณะที่เขียนขึ้นครั้งแรกยังไม่มี FR ใดรองรับความสามารถนี้จริง — ปัจจุบันมี [[acceptance-criteria#FR-32 (กลาง) — เรียกดูประวัติการแก้ไขผลประเมินรายอาคาร|FR-32]] (ฟีเจอร์ 16, [[test-cases/audit-trail-building|test-cases/audit-trail-building.md]]) รองรับช่องทางเรียกดูนี้แล้ว จึงผูก FR-32 AC-4 (ผู้ดูแลระบบเข้าถึงได้ไม่จำกัดทีม) เพิ่มเป็นรหัสรอง เนื่องจากทั้งสอง TC ใช้บัญชีผู้ดูแลระบบเปิดดูประวัติผ่านช่องทางเดียวกับที่ FR-32 นิยามไว้ — รหัสหลักที่ทดสอบยังคงเป็น NFR-05 (การมีอยู่/ความถูกต้องของระเบียนประวัติ) ไม่ใช่ FR-32 (สิทธิ์การเข้าถึง ซึ่งทดสอบละเอียดแยกในไฟล์ audit-trail-building.md แล้ว)
