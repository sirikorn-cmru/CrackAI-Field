# Acceptance Criteria

เอกสารนี้กำหนดเกณฑ์ยอมรับ (Given-When-Then) ของทุกรหัส FR/NFR ใน [[backlog]] จัดกลุ่มตามหัวข้อฟีเจอร์เดียวกับ [[feature-list]] เพื่อให้ไล่อ่านคู่กันได้ง่าย อ้างอิงพฤติกรรมจาก [[feature-list]] และ [[user-journey]] เป็นหลัก (spec ต้นทางคือ [[20260828-01-flood-damage-survey]])

ระดับความสำคัญ (สูง/กลาง/ต่ำ) ที่กำกับท้ายรหัสแต่ละหัวข้อย่อยดึงมาจาก [[backlog]] โดยตรงเสมอ

## 1. บันทึกข้อมูลอาคารและสภาพแวดล้อม

อ้างอิง: [[feature-list#1. บันทึกข้อมูลอาคารและสภาพแวดล้อม|ฟีเจอร์ 1]] · [[user-journey#Journey: ผู้สำรวจภาคสนามลงพื้นที่สำรวจอาคาร|journey ผู้สำรวจภาคสนาม]] · บทบาท: ผู้สำรวจภาคสนาม

#### FR-01 (สูง) — [[20260828-01-flood-damage-survey#4.1 ข้อมูลอาคารและสภาพแวดล้อม|บันทึกข้อมูลทั่วไปของอาคาร]]

- AC-1: Given ผู้สำรวจภาคสนามเข้าสู่ระบบและเริ่มบันทึกแบบสำรวจอาคารใหม่ (ออนไลน์หรือออฟไลน์ก็ได้), When กรอกข้อมูลทั่วไปของอาคารครบทุกช่องบังคับ (ชื่ออาคาร เจ้าของ ที่ตั้ง การใช้สอย กรรมสิทธิ์) แล้วบันทึก, Then ระบบบันทึกข้อมูลทั่วไปไว้กับรายการสำรวจอาคารนั้นสำเร็จและอนุญาตให้ไปหมวดถัดไปได้
- AC-2: Given ผู้สำรวจกำลังกรอกข้อมูลทั่วไปของอาคาร, When เว้นว่างช่องข้อมูลบังคับข้อใดข้อหนึ่งแล้วพยายามไปหมวดถัดไป, Then ระบบแจ้งเตือนว่าต้องกรอกข้อมูลให้ครบก่อน และไม่อนุญาตให้ข้ามหมวดจนกว่าจะกรอกครบ

#### FR-02 (สูง) — [[20260828-01-flood-damage-survey#4.1 ข้อมูลอาคารและสภาพแวดล้อม|บันทึกพิกัด GPS ของอาคาร]]

- AC-1: Given ผู้สำรวจอยู่ที่หน้างานและเปิดหน้าบันทึกข้อมูลอาคาร, When ระบบขอตำแหน่งปัจจุบันจากอุปกรณ์และรับสัญญาณ GPS ได้ตามเกณฑ์ความแม่นยำ (NFR-06), Then ระบบบันทึกพิกัด GPS ผูกกับอาคารนั้นสำเร็จ
- AC-2: Given อุปกรณ์ยังไม่สามารถรับสัญญาณ GPS ที่มีความแม่นยำตามเกณฑ์ได้, When ผู้สำรวจพยายามบันทึกพิกัด, Then ระบบแจ้งสถานะว่ายังไม่สามารถระบุพิกัดที่แม่นยำเพียงพอ และไม่บันทึกพิกัดนั้นจนกว่าจะรับสัญญาณได้ตามเกณฑ์

#### FR-03 (สูง) — [[20260828-01-flood-damage-survey#4.1 ข้อมูลอาคารและสภาพแวดล้อม|บันทึกข้อมูลทางกายภาพของอาคาร]]

- AC-1: Given ผู้สำรวจกรอกข้อมูลทั่วไปของอาคารแล้ว, When กรอกข้อมูลทางกายภาพ (จำนวนชั้น พื้นที่ใช้สอย ชนิดโครงสร้าง วัสดุหลัก) ครบถ้วนแล้วบันทึก, Then ระบบบันทึกข้อมูลทางกายภาพไว้กับอาคารนั้นสำเร็จ
- AC-2: Given ผู้สำรวจกรอกจำนวนชั้นหรือพื้นที่เป็นค่าที่ไม่ใช่ตัวเลขหรือเป็นค่าติดลบ, When พยายามบันทึก, Then ระบบแจ้งเตือนว่าข้อมูลไม่ถูกต้องและไม่บันทึกค่านั้น

#### FR-04 (สูง) — [[20260828-01-flood-damage-survey#4.1 ข้อมูลอาคารและสภาพแวดล้อม|บันทึกอันตรายของสภาพแวดล้อมโดยรอบอาคาร]]

- AC-1: Given ผู้สำรวจตรวจพบอันตรายจากสภาพแวดล้อมโดยรอบ (เช่น อาคารข้างเคียง ลาดเชิงเขา ดินทรุดตัว), When เลือก/บันทึกรายการอันตรายที่พบ, Then ระบบบันทึกรายการอันตรายโดยรอบไว้กับอาคารนั้นสำเร็จ
- AC-2: Given ไม่พบอันตรายจากสภาพแวดล้อมโดยรอบเลย, When ผู้สำรวจระบุว่า "ไม่พบอันตราย" แล้วบันทึก, Then ระบบบันทึกสถานะไม่พบอันตรายและอนุญาตให้ไปหมวดถัดไปได้โดยไม่บังคับให้เลือกอันตรายใดๆ

#### NFR-06 (กลาง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Accuracy (ความแม่นยำของพิกัด GPS)]]

- AC-1: Given อุปกรณ์รับสัญญาณ GPS ได้ขณะบันทึกอาคาร, When ระบบบันทึกพิกัด, Then ค่าความแม่นยำ (accuracy) ของพิกัดต้องอยู่ในเกณฑ์ที่ยอมรับได้สำหรับงานสำรวจภาคสนาม มิฉะนั้นระบบต้องแจ้งเตือนผู้สำรวจว่าความแม่นยำต่ำกว่าเกณฑ์ก่อนยืนยันบันทึก

## 2. ประเมินความเสียหายโครงสร้างและส่วนประกอบอาคารแยกตามหมวด

อ้างอิง: [[feature-list#2. ประเมินความเสียหายโครงสร้างและส่วนประกอบอาคารแยกตามหมวด|ฟีเจอร์ 2]] · บทบาท: ผู้สำรวจภาคสนาม

#### FR-05 (สูง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|บันทึกความเสียหายที่สังเกตจากภายนอกอาคาร]]

- AC-1: Given ผู้สำรวจตรวจสอบภายนอกอาคาร, When บันทึกลักษณะ/ระดับความเสียหายที่สังเกตเห็นจากภายนอก, Then ระบบบันทึกข้อมูลความเสียหายภายนอกไว้กับอาคารนั้นสำเร็จ
- AC-2: Given ผู้สำรวจยังไม่เลือกระดับความเสียหายของหมวดภายนอกอาคาร, When พยายามไปหมวดถัดไป, Then ระบบแจ้งเตือนให้กรอกหมวดนี้ให้ครบก่อน

#### FR-06 (สูง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|บันทึกความเสียหายของโครงสร้างอาคารแยกตามชนิดวัสดุและตำแหน่ง]]

- AC-1: Given ผู้สำรวจตรวจพบความเสียหายโครงสร้าง, When เลือกชนิดวัสดุ (ไม้/คอนกรีตเสริมเหล็ก/เหล็กรูปพรรณ) และระบุตำแหน่ง/ระดับความเสียหาย, Then ระบบบันทึกความเสียหายโครงสร้างแยกตามชนิดวัสดุและตำแหน่งสำเร็จ
- AC-2: Given อาคารมีโครงสร้างมากกว่าหนึ่งชนิดวัสดุ, When ผู้สำรวจบันทึกความเสียหายของแต่ละชนิดวัสดุแยกกัน, Then ระบบเก็บบันทึกแยกตามชนิดวัสดุโดยไม่ปะปนกัน

#### FR-07 (กลาง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|บันทึกความเสียหายของโครงหลังคา]]

- AC-1: Given ผู้สำรวจตรวจพบความเสียหายของโครงหลังคา, When บันทึกระดับความเสียหายของโครงหลังคา, Then ระบบบันทึกข้อมูลไว้กับอาคารนั้นสำเร็จ

#### FR-08 (สูง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|บันทึกความเสียหายของส่วนประกอบอาคาร]]

- AC-1: Given ผู้สำรวจตรวจพบความเสียหายของส่วนประกอบอาคาร (ผนัง/ฝ้าเพดาน/วัสดุมุงหลังคา), When เลือกส่วนประกอบและระบุระดับความเสียหาย, Then ระบบบันทึกความเสียหายของส่วนประกอบอาคารแยกตามชนิดสำเร็จ
- AC-2: Given ผู้สำรวจข้ามหมวดส่วนประกอบอาคารโดยไม่กรอก, When พยายามไปหมวดถัดไป, Then ระบบแจ้งเตือนให้กรอกให้ครบก่อน

#### FR-09 (กลาง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|บันทึกความเสียหายของระบบไฟฟ้าและระบบอื่นๆ]]

- AC-1: Given ผู้สำรวจตรวจพบความเสียหายของระบบไฟฟ้า/ระบบอื่นๆ, When บันทึกระดับความเสียหายของระบบไฟฟ้า, Then ระบบบันทึกข้อมูลไว้กับอาคารนั้นสำเร็จ

## 3. สรุปผลประเมินเป็น 3 ระดับสีพร้อมเกณฑ์อ้างอิงคู่มือ

อ้างอิง: [[feature-list#3. สรุปผลประเมินเป็น 3 ระดับสีพร้อมเกณฑ์อ้างอิงคู่มือ|ฟีเจอร์ 3]] · บทบาท: ผู้สำรวจภาคสนาม

#### FR-10 (สูง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|สรุปผลการประเมินความเสียหายเป็น 3 ระดับสี]]

- AC-1: Given ผู้สำรวจกรอกความเสียหายครบทุกหมวดที่บังคับแล้ว, When สรุปผลประเมินเป็นระดับสี, Then ระบบแสดง/บันทึกผลสรุปเป็นหนึ่งในสามระดับ (เขียว/เหลือง/แดง) พร้อมข้อแนะนำเพิ่มเติมที่สอดคล้องกับระดับนั้น
- AC-2: Given ผู้สำรวจยังกรอกความเสียหายไม่ครบทุกหมวดที่บังคับ, When พยายามสรุปผลเป็นระดับสี, Then ระบบไม่อนุญาตให้สรุปผลจนกว่าจะกรอกข้อมูลที่จำเป็นครบถ้วน และแจ้งเตือนหมวดที่ยังขาด

#### FR-11 (สูง) — [[20260828-01-flood-damage-survey#4.2 การประเมินความเสียหายโครงสร้าง|แสดงเกณฑ์อ้างอิงจากคู่มือประกอบแต่ละหมวดการประเมินในแอป]]

- AC-1: Given ผู้สำรวจกำลังกรอกหมวดการประเมินความเสียหายหมวดใดหมวดหนึ่ง, When เลือกเปิดดูเกณฑ์อ้างอิงคู่มือของหมวดนั้น, Then ระบบแสดงเนื้อหาเกณฑ์อ้างอิงคู่มือ (deep link ตามเลขหน้าที่เกี่ยวข้อง) โดยไม่ต้องออกจากหน้ากรอกข้อมูลปัจจุบัน
- AC-2: Given อุปกรณ์ไม่มีสัญญาณอินเทอร์เน็ตที่หน้างาน, When ผู้สำรวจเปิดดูเกณฑ์อ้างอิงคู่มือ, Then ระบบยังคงแสดงเนื้อหาเกณฑ์อ้างอิงได้ตามปกติ สอดคล้องกับการทำงานออฟไลน์เต็มรูปแบบ ([[acceptance-criteria#NFR-01 (สูง) — Availability Offline Support|NFR-01]])

## 4. ถ่ายภาพและวิเคราะห์รอยร้าวด้วย AI (Human-in-the-loop)

อ้างอิง: [[feature-list#4. ถ่ายภาพและวิเคราะห์รอยร้าวด้วย AI (Human-in-the-loop)|ฟีเจอร์ 4]] · บทบาท: ผู้สำรวจภาคสนาม

#### FR-12 (สูง) — [[20260828-01-flood-damage-survey#4.3 ภาพถ่ายและ AI วิเคราะห์รอยร้าว|ถ่ายภาพประกอบความเสียหายผูกกับตำแหน่ง/บริเวณ]]

- AC-1: Given ผู้สำรวจต้องการบันทึกภาพประกอบความเสียหาย ณ ตำแหน่ง/บริเวณหนึ่ง, When ถ่ายภาพและระบุตำแหน่ง/บริเวณที่ภาพนั้นเกี่ยวข้อง, Then ระบบบันทึกภาพผูกกับตำแหน่งนั้นไว้กับอาคารสำเร็จ
- AC-2: Given อุปกรณ์ไม่มีสัญญาณอินเทอร์เน็ต, When ผู้สำรวจถ่ายภาพประกอบ, Then ระบบเก็บภาพไว้ในเครื่องก่อนและรอซิงค์เมื่อมีสัญญาณ โดยไม่บล็อกการทำงานต่อ

#### FR-13 (สูง) — [[20260828-01-flood-damage-survey#4.3 ภาพถ่ายและ AI วิเคราะห์รอยร้าว|วิเคราะห์ภาพถ่ายรอยร้าวด้วย AI]]

- AC-1: Given มีภาพถ่ายรอยร้าวที่ผูกกับตำแหน่งแล้ว, When ผู้สำรวจสั่งให้ AI วิเคราะห์ภาพ (ทำงานได้แม้ออฟไลน์ ตามขอบเขตฟีเจอร์ 1-6 ใน NFR-01), Then ระบบแสดงผลประมาณความกว้างรอยแตกร้าวและระดับความเสียหายที่ AI เสนอเป็นค่าตั้งต้น (draft) ให้ผู้สำรวจเห็นก่อนยืนยัน

> หมายเหตุ: กรณี AI ไม่สามารถวิเคราะห์ภาพได้ (เช่น ภาพเบลอ แสงไม่พอ หรือไม่พบรอยร้าวในภาพ) ยังไม่มี FR ใดระบุพฤติกรรมที่ระบบควรแสดงไว้ — ดูหัวข้อ `NEEDS_NEW_REQUIREMENT` ท้ายรายงานของ agent นี้

#### FR-14 (สูง) — [[20260828-01-flood-damage-survey#4.3 ภาพถ่ายและ AI วิเคราะห์รอยร้าว|ให้ผู้สำรวจยืนยัน/แก้ไขผลวิเคราะห์ของ AI ก่อนบันทึกเป็นผลจริง]]

- AC-1: Given AI เสนอผลวิเคราะห์ความกว้างรอยร้าวและระดับความเสียหายเป็นค่าตั้งต้นแล้ว, When ผู้สำรวจตรวจสอบแล้วเห็นว่าถูกต้องและกดยืนยัน, Then ระบบบันทึกผลนั้นเป็นผลจริงของอาคารนั้น พร้อมบันทึกว่าเป็นผลที่ยืนยันตามที่ AI เสนอ (ไม่มีการแก้ไข)
- AC-2: Given AI เสนอผลวิเคราะห์เป็นค่าตั้งต้น, When ผู้สำรวจเห็นว่าไม่ถูกต้องและแก้ไขค่าความกว้างรอยร้าว/ระดับความเสียหายก่อนกดยืนยัน, Then ระบบบันทึกค่าที่ผู้สำรวจแก้ไขเป็นผลจริง และบันทึกประวัติว่าเดิม AI เสนอค่าใด ผู้สำรวจแก้เป็นค่าใด ([[acceptance-criteria#NFR-05 (สูง) — Auditability Accountability (ประวัติการแก้ไขผล AI)|NFR-05]])
- AC-3: Given AI ประมวลผลภาพเสร็จและเสนอผลตั้งต้นแล้ว, When ผู้สำรวจยังไม่กดยืนยัน/แก้ไข, Then ระบบต้องไม่บันทึกผลของ AI เป็นผลสรุปสุดท้ายโดยอัตโนมัติไม่ว่าจะผ่านไปนานเท่าใด

#### NFR-05 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Auditability / Accountability (ประวัติการแก้ไขผล AI)]]

- AC-1: Given ผู้สำรวจยืนยันหรือแก้ไขผลวิเคราะห์ของ AI, When การกระทำนั้นถูกบันทึก, Then ระบบเก็บประวัติการเปลี่ยนแปลง (ค่าที่ AI เสนอเดิม ค่าที่ผู้สำรวจยืนยัน/แก้ไข ผู้ทำรายการ และเวลา) ไว้ตรวจสอบย้อนหลังได้ครบถ้วน และประวัตินี้ต้องไม่สามารถแก้ไขย้อนหลังได้

## 5. วาดภาพประกอบเพิ่มเติม

อ้างอิง: [[feature-list#5. วาดภาพประกอบเพิ่มเติม|ฟีเจอร์ 5]] · บทบาท: ผู้สำรวจภาคสนาม

#### FR-15 (กลาง) — [[20260828-01-flood-damage-survey#4.3 ภาพถ่ายและ AI วิเคราะห์รอยร้าว|วาด/เขียนภาพประกอบเพิ่มเติม]]

- AC-1: Given ผู้สำรวจต้องการระบุตำแหน่งความเสียหายที่ถ่ายภาพลำบาก, When เลือกวาด/เขียนภาพประกอบเพิ่มเติมในหมวด "พื้นที่สำหรับวาดภาพประกอบที่จำเป็น", Then ระบบบันทึกภาพวาดนั้นไว้กับอาคารสำเร็จ
- AC-2: Given ผู้สำรวจไม่มีความจำเป็นต้องวาดภาพประกอบเพิ่มเติม, When ข้ามหมวดนี้ไปโดยไม่วาด, Then ระบบอนุญาตให้ข้ามได้โดยไม่บังคับ (เป็นหมวดไม่บังคับ)

## 6. บันทึกข้อมูลผู้สำรวจและระยะเวลาการสำรวจ

อ้างอิง: [[feature-list#6. บันทึกข้อมูลผู้สำรวจและระยะเวลาการสำรวจ|ฟีเจอร์ 6]] · บทบาท: ผู้สำรวจภาคสนาม

#### FR-16 (สูง) — [[20260828-01-flood-damage-survey#4.4 ผู้สำรวจ การรับรองผล และการมอบหมายงาน|บันทึกข้อมูลผู้สำรวจและหัวหน้าผู้สำรวจ]]

- AC-1: Given ผู้สำรวจเริ่มสรุปแบบสำรวจอาคาร, When กรอกรายชื่อผู้สำรวจ (สูงสุด 3 คน) และหัวหน้าผู้สำรวจพร้อมหน่วยงาน/โทรศัพท์/ตำแหน่ง, Then ระบบบันทึกข้อมูลผู้สำรวจไว้กับอาคารนั้นสำเร็จ
- AC-2: Given มีการกรอกรายชื่อผู้สำรวจแล้ว 3 คน, When ผู้สำรวจพยายามเพิ่มรายชื่อคนที่ 4, Then ระบบไม่อนุญาตให้เพิ่มเกิน 3 คน และแจ้งเตือนจำนวนสูงสุดที่กำหนด

#### FR-17 (กลาง) — [[20260828-01-flood-damage-survey#4.4 ผู้สำรวจ การรับรองผล และการมอบหมายงาน|บันทึกวันที่และเวลาเริ่ม/เวลาแล้วเสร็จของการสำรวจ]]

- AC-1: Given ผู้สำรวจเริ่มต้นสำรวจอาคารหนึ่ง, When ระบบบันทึกเวลาเริ่มสำรวจ และเมื่อผู้สำรวจกรอกข้อมูลครบและยืนยันเสร็จสิ้น ระบบบันทึกเวลาแล้วเสร็จ, Then ระบบเก็บวันที่และเวลาเริ่ม/แล้วเสร็จของการสำรวจอาคารนั้นไว้ครบถ้วน

## 7. ตรวจทานและรับรองผลสำรวจด้วยลายเซ็นดิจิทัล

อ้างอิง: [[feature-list#7. ตรวจทานและรับรองผลสำรวจด้วยลายเซ็นดิจิทัล|ฟีเจอร์ 7]] · บทบาท: หัวหน้าผู้สำรวจ

#### FR-19 (สูง) — [[20260828-01-flood-damage-survey#4.4 ผู้สำรวจ การรับรองผล และการมอบหมายงาน|หัวหน้าผู้สำรวจตรวจทานผลการสำรวจของทีมก่อนรับรอง]]

- AC-1: Given หัวหน้าผู้สำรวจตรวจทานผลการสำรวจที่ทีมกรอกครบทุกอาคาร, When เห็นว่าผลถูกต้องครบถ้วน, Then ระบบอนุญาตให้ดำเนินการต่อไปสู่ขั้นตอนลงลายมือชื่อรับรอง (FR-18)
- AC-2: Given หัวหน้าผู้สำรวจตรวจทานแล้วพบว่าข้อมูลไม่ครบถ้วน/ไม่ถูกต้อง, When เลือกส่งกลับให้ทีมแก้ไข, Then ระบบเปลี่ยนสถานะของรายการสำรวจนั้นเป็น "ส่งกลับแก้ไข" แจ้งผู้สำรวจที่เกี่ยวข้อง และไม่อนุญาตให้ลงลายมือชื่อรับรองจนกว่าจะแก้ไขและส่งกลับมาตรวจทานใหม่

#### FR-18 (สูง) — [[20260828-01-flood-damage-survey#4.4 ผู้สำรวจ การรับรองผล และการมอบหมายงาน|ลงลายมือชื่อดิจิทัลของหัวหน้าผู้สำรวจเพื่อรับรองผลสรุป]]

- AC-1: Given ผลการสำรวจอาคารถูกตรวจทานว่าครบถ้วนถูกต้องแล้ว (FR-19), When หัวหน้าผู้สำรวจลงลายมือชื่อดิจิทัล (touch signature) เพื่อรับรอง, Then ระบบบันทึกลายมือชื่อผูกกับผลสรุปของอาคารนั้นและเปลี่ยนสถานะเป็น "รับรองแล้ว" สำเร็จ
- AC-2: Given หัวหน้าผู้สำรวจยังไม่ได้ลงลายมือชื่อ, When พยายามปิดหน้าจอหรือดำเนินการอื่นโดยไม่ลงนาม, Then สถานะของผลสรุปยังคงเป็น "รอรับรอง" และไม่ถือว่าผลนั้นได้รับการรับรองอย่างเป็นทางการ

## 8. มอบหมายงานสำรวจให้ทีม

อ้างอิง: [[feature-list#8. มอบหมายงานสำรวจให้ทีม|ฟีเจอร์ 8]] · บทบาท: หัวหน้าผู้สำรวจ

#### FR-20 (กลาง) — [[20260828-01-flood-damage-survey#4.4 ผู้สำรวจ การรับรองผล และการมอบหมายงาน|หัวหน้าผู้สำรวจมอบหมายงานสำรวจอาคาร/พื้นที่ให้สมาชิกทีม]]

- AC-1: Given หัวหน้าผู้สำรวจต้องการกระจายงานให้ทีม, When สร้างรายการอาคาร/พื้นที่ที่ต้องสำรวจและมอบหมายให้สมาชิกทีมที่ระบุ, Then ระบบบันทึกการมอบหมายงานและสมาชิกทีมที่ได้รับมอบหมายเห็นรายการงานของตนเอง
- AC-2: Given ยังไม่มีบัญชีผู้ใช้บทบาทผู้สำรวจภาคสนามให้เลือกมอบหมาย, When หัวหน้าผู้สำรวจพยายามมอบหมายงาน, Then ระบบแจ้งเตือนว่าไม่มีสมาชิกให้เลือกและแนะนำให้ผู้ดูแลระบบสร้างบัญชีก่อน (เชื่อมโยงกับ [[feature-list#9. จัดการผู้ใช้และสิทธิ์การเข้าถึง|ฟีเจอร์ 9]])

## 9. จัดการผู้ใช้และสิทธิ์การเข้าถึง

อ้างอิง: [[feature-list#9. จัดการผู้ใช้และสิทธิ์การเข้าถึง|ฟีเจอร์ 9]] · บทบาท: ผู้ดูแลระบบ

#### FR-21 (สูง) — [[20260828-01-flood-damage-survey#4.5 การจัดการผู้ใช้ สิทธิ์ และภาพรวมผลสำรวจ|จัดการผู้ใช้และสิทธิ์การเข้าถึงตามบทบาท]]

- AC-1: Given ผู้ดูแลระบบเข้าสู่ระบบ, When สร้างบัญชีผู้ใช้ใหม่พร้อมกำหนดบทบาท (ผู้สำรวจภาคสนาม/หัวหน้าผู้สำรวจ/ผู้ดูแลระบบ/หน่วยงานส่วนกลาง), Then ระบบสร้างบัญชีผู้ใช้พร้อมบทบาทที่กำหนดสำเร็จ
- AC-2: Given มีบัญชีผู้ใช้อยู่แล้ว, When ผู้ดูแลระบบแก้ไขข้อมูล/บทบาทของบัญชีนั้น, Then ระบบบันทึกการเปลี่ยนแปลงและมีผลกับสิทธิ์การเข้าถึงของผู้ใช้นั้นในการเข้าใช้งานครั้งถัดไป
- AC-3: Given บัญชีผู้ใช้ไม่ควรเข้าถึงระบบอีกต่อไป, When ผู้ดูแลระบบปิดการใช้งานบัญชีนั้น, Then ระบบปฏิเสธการเข้าสู่ระบบของบัญชีนั้นตั้งแต่ครั้งถัดไป

#### NFR-08 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Security (ข้อมูลเข้าถึงได้เฉพาะผู้ใช้ที่มีสิทธิ์ตามบทบาท)]]

- AC-1: Given ผู้ใช้แต่ละบทบาทมีสิทธิ์การเข้าถึงข้อมูลตามที่กำหนดไว้ (FR-21), When ผู้ใช้พยายามเข้าถึงข้อมูล/ฟังก์ชันที่อยู่นอกเหนือบทบาทของตน, Then ระบบต้องปฏิเสธการเข้าถึงนั้นและไม่แสดงข้อมูลที่ไม่มีสิทธิ์

## 10. Dashboard ภาพรวมผลสำรวจ

อ้างอิง: [[feature-list#10. Dashboard ภาพรวมผลสำรวจ|ฟีเจอร์ 10]] · บทบาท: หน่วยงานส่วนกลาง/ผู้บริหาร

#### FR-22 (สูง) — [[20260828-01-flood-damage-survey#4.5 การจัดการผู้ใช้ สิทธิ์ และภาพรวมผลสำรวจ|แสดง dashboard ภาพรวมผลสำรวจ]]

- AC-1: Given มีข้อมูลผลสำรวจอาคารในระบบ, When หน่วยงานส่วนกลาง/ผู้บริหารเปิดหน้า dashboard, Then ระบบแสดงจำนวนอาคารที่สำรวจแล้วและสัดส่วนตามระดับสี (เขียว/เหลือง/แดง) แยกตามพื้นที่/จังหวัดถูกต้องตรงกับข้อมูลจริง
- AC-2: Given ยังไม่มีอาคารใดถูกสำรวจในพื้นที่หนึ่ง, When เปิด dashboard กรองดูพื้นที่นั้น, Then ระบบแสดงสถานะว่ายังไม่มีข้อมูล แทนที่จะแสดงข้อผิดพลาดหรือค่าว่างที่สับสน

## 11. ส่งออกรายงานผลการสำรวจ

อ้างอิง: [[feature-list#11. ส่งออกรายงานผลการสำรวจ|ฟีเจอร์ 11]] · บทบาท: หน่วยงานส่วนกลาง/ผู้บริหาร

#### FR-23 (กลาง) — [[20260828-01-flood-damage-survey#4.5 การจัดการผู้ใช้ สิทธิ์ และภาพรวมผลสำรวจ|ส่งออกรายงานผลการสำรวจ]]

- AC-1: Given หน่วยงานส่วนกลาง/ผู้บริหารต้องการนำผลสำรวจไปใช้นอกระบบ, When เลือกส่งออกรายงานรายอาคารหรือสรุปภาพรวม, Then ระบบสร้างไฟล์รายงานที่มีข้อมูลตรงกับที่แสดงในระบบให้ดาวน์โหลดสำเร็จ (รูปแบบไฟล์เป็นไปตามที่จะตัดสินใจใน `technology-stack.md`)
- AC-2: Given เลือกส่งออกโดยไม่มีข้อมูลตรงเงื่อนไขที่กรองไว้เลย, When สั่งส่งออก, Then ระบบแจ้งเตือนว่าไม่มีข้อมูลให้ส่งออกแทนที่จะสร้างไฟล์ว่างเปล่าโดยไม่แจ้งอะไร

## 12. ค้นหา/กรองรายการอาคารที่สำรวจแล้ว

อ้างอิง: [[feature-list#12. ค้นหา/กรองรายการอาคารที่สำรวจแล้ว|ฟีเจอร์ 12]] · บทบาท: หน่วยงานส่วนกลาง/ผู้บริหาร, หัวหน้าผู้สำรวจ

#### FR-24 (กลาง) — [[20260828-01-flood-damage-survey#4.5 การจัดการผู้ใช้ สิทธิ์ และภาพรวมผลสำรวจ|ค้นหา/กรองรายการอาคารที่สำรวจแล้ว]]

- AC-1: Given มีรายการอาคารที่สำรวจแล้วในระบบ, When ผู้ใช้ (หัวหน้าผู้สำรวจ/หน่วยงานส่วนกลาง) ค้นหา/กรองตามพื้นที่ ระดับสี ช่วงวันที่ หรือผู้สำรวจ, Then ระบบแสดงเฉพาะรายการที่ตรงเงื่อนไขทั้งหมดที่เลือกถูกต้อง
- AC-2: Given เงื่อนไขที่กรองไม่ตรงกับรายการใดเลย, When ค้นหา, Then ระบบแสดงข้อความว่าไม่พบรายการที่ตรงเงื่อนไข แทนที่จะแสดงหน้าว่างเปล่าโดยไม่มีคำอธิบาย

## 13. การทำงานออฟไลน์และซิงค์ข้อมูลภาคสนาม

อ้างอิง: [[feature-list#13. การทำงานออฟไลน์และซิงค์ข้อมูลภาคสนาม|ฟีเจอร์ 13]] · บทบาท: ผู้สำรวจภาคสนาม

#### NFR-01 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Availability / Offline Support]]

- AC-1: Given อุปกรณ์ของผู้สำรวจไม่มีสัญญาณอินเทอร์เน็ตที่หน้างาน, When ผู้สำรวจกรอกแบบสำรวจครบทุกหมวด (ฟีเจอร์ 1-6 รวมถ่ายภาพและวิเคราะห์ด้วย AI), Then ระบบต้องให้ทำงานได้ครบทุกฟังก์ชันหลักของการสำรวจโดยไม่ต้องพึ่งพาการเชื่อมต่อเครือข่ายเลย

#### NFR-02 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Performance / Reliability]]

- AC-1: Given อุปกรณ์กลับมามีสัญญาณอินเทอร์เน็ตหลังทำงานออฟไลน์, When ระบบเริ่มกระบวนการซิงค์ข้อมูลและภาพถ่ายที่ค้างอยู่ขึ้นเซิร์ฟเวอร์, Then การซิงค์ต้องดำเนินไปสำเร็จโดยอัตโนมัติโดยผู้ใช้ไม่ต้องเข้าไปแทรกแซงเอง
- AC-2: Given การซิงค์ถูกขัดจังหวะกลางคัน (สัญญาณหลุดระหว่างซิงค์), When อุปกรณ์กลับมามีสัญญาณอีกครั้ง, Then ระบบซิงค์ต่อจากจุดที่ค้างได้โดยไม่ทำข้อมูลซ้ำซ้อนหรือสูญหาย

#### NFR-03 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Data Integrity]]

- AC-1: Given หลายอุปกรณ์แก้ไขข้อมูลอาคารเดียวกันขณะออฟไลน์แยกกัน, When ทั้งสองอุปกรณ์กลับมาซิงค์พร้อมกัน, Then ระบบต้องตรวจจับความขัดแย้งของข้อมูลและจัดการตามนโยบายที่กำหนดโดยไม่ทำให้ข้อมูลที่บันทึกไว้สูญหายเงียบๆ (ต้องมีร่องรอย/แจ้งเตือนความขัดแย้งให้ผู้เกี่ยวข้องทราบ)

#### NFR-04 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Usability / Compatibility]]

- AC-1: Given ผู้สำรวจใช้งานแอปบนมือถือ/แท็บเล็ตกลางแจ้งภายใต้สภาพหน้างานหลังน้ำท่วม (แสงจ้า/ฝุ่น/ความชื้น), When ใช้งานฟังก์ชันบันทึกแบบสำรวจ, Then หน้าจอและการควบคุมต้องใช้งานได้จริงในสภาพแวดล้อมกลางแจ้งดังกล่าว (อ่านง่าย กดง่าย)

#### NFR-07 (กลาง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Scalability]]

- AC-1: Given เกิดเหตุการณ์อุทกภัยและมีหลายทีมสำรวจจำนวนมากพร้อมกัน, When ทุกทีมกลับมามีสัญญาณและซิงค์ข้อมูลพร้อมกันในช่วงเวลาใกล้เคียงกัน, Then ระบบต้องรองรับปริมาณการซิงค์พร้อมกันจำนวนมากได้โดยไม่ล่มหรือทำข้อมูลสูญหาย

## 14. ยืนยันตัวตนและเข้าสู่ระบบ

อ้างอิง: [[feature-list#14. ยืนยันตัวตนและเข้าสู่ระบบ|ฟีเจอร์ 14]] · บทบาท: ทุกบทบาท (FR-27/NFR-09 เฉพาะผู้สำรวจภาคสนาม)

#### FR-25 (สูง) — [[20260828-01-flood-damage-survey#4.6 การยืนยันตัวตนและการเข้าสู่ระบบ|ยืนยันตัวตนผู้ใช้ (เข้าสู่ระบบ/ออกจากระบบ)]]

- AC-1: Given ผู้ใช้มีบัญชีที่ถูกต้องและมีสัญญาณอินเทอร์เน็ต, When กรอกชื่อผู้ใช้/รหัสผ่านที่ถูกต้องแล้วเข้าสู่ระบบ, Then ระบบยืนยันตัวตนสำเร็จและนำผู้ใช้เข้าสู่หน้าหลักตามบทบาทของตน
- AC-2: Given ผู้ใช้กรอกชื่อผู้ใช้/รหัสผ่านไม่ถูกต้อง, When พยายามเข้าสู่ระบบ, Then ระบบปฏิเสธการเข้าสู่ระบบและแจ้งข้อความว่าข้อมูลเข้าสู่ระบบไม่ถูกต้อง โดยไม่เปิดเผยว่าผิดที่ชื่อผู้ใช้หรือรหัสผ่าน
- AC-3: Given ผู้ใช้เข้าสู่ระบบอยู่, When เลือกออกจากระบบ, Then ระบบยุติ session ปัจจุบันและต้องเข้าสู่ระบบใหม่ก่อนใช้งานฟังก์ชันใดๆ อีกครั้ง

#### FR-26 (สูง) — [[20260828-01-flood-damage-survey#4.6 การยืนยันตัวตนและการเข้าสู่ระบบ|บังคับสิทธิ์การเข้าถึงฟังก์ชัน/หน้าจอตามบทบาทหลังเข้าสู่ระบบ]]

- AC-1: Given ผู้ใช้เข้าสู่ระบบสำเร็จด้วยบทบาทหนึ่ง (ตามที่ผู้ดูแลระบบกำหนดใน FR-21), When ผู้ใช้ใช้งานระบบ, Then ระบบแสดงและอนุญาตเฉพาะฟังก์ชัน/หน้าจอที่ตรงกับบทบาทนั้นเท่านั้น
- AC-2: Given ผู้ใช้พยายามเข้าถึงหน้าจอที่อยู่นอกเหนือสิทธิ์ของบทบาทตนโดยตรง, When ระบบตรวจสอบสิทธิ์, Then ระบบปฏิเสธการเข้าถึงและแจ้งว่าไม่มีสิทธิ์เข้าถึง

#### FR-27 (สูง) — [[20260828-01-flood-damage-survey#4.6 การยืนยันตัวตนและการเข้าสู่ระบบ|เข้าสู่ระบบและใช้งานแอปขณะไม่มีการเชื่อมต่ออินเทอร์เน็ต]]

- AC-1: Given ผู้สำรวจภาคสนามเคยเข้าสู่ระบบสำเร็จจากเซิร์ฟเวอร์มาก่อนและอุปกรณ์มี credential/session ที่แคชไว้ที่ยังไม่หมดอายุ, When เปิดแอปที่หน้างานโดยไม่มีสัญญาณอินเทอร์เน็ต, Then ระบบอนุญาตให้เข้าสู่ระบบด้วย credential/session ที่แคชไว้และใช้งานฟังก์ชันสำรวจภาคสนามได้ตามปกติ
- AC-2: Given credential/session ที่แคชไว้หมดอายุแล้วตามเกณฑ์ที่กำหนด ([[acceptance-criteria#NFR-09 (สูง) — Security (Offline Session Expiry)|NFR-09]]), When ผู้สำรวจพยายามเข้าสู่ระบบขณะไม่มีสัญญาณอินเทอร์เน็ต, Then ระบบปฏิเสธการเข้าสู่ระบบด้วย credential ที่แคชไว้ และแจ้งว่าต้องเชื่อมต่อสัญญาณเพื่อยืนยันตัวตนใหม่ก่อนใช้งานต่อ

#### NFR-09 (สูง) — [[20260828-01-flood-damage-survey#5. Non-Functional Requirements|Security (Offline Session Expiry)]]

- AC-1: Given ผู้สำรวจเข้าสู่ระบบขณะออฟไลน์ด้วย credential/session ที่แคชไว้ (FR-27), When ครบกำหนดอายุการใช้งานที่จำกัดไว้ หรืออุปกรณ์กลับมามีสัญญาณอินเทอร์เน็ต, Then ระบบบังคับให้ยืนยันตัวตนใหม่กับเซิร์ฟเวอร์ก่อนอนุญาตให้ใช้งานต่อ เพื่อจำกัดความเสี่ยงจากอุปกรณ์สูญหาย/ถูกขโมย
