### รหัส FR/NFR ที่เพิ่ม
เนื่องจากเป็น requirement แรกของโปรเจกต์ (ไม่มีรหัสเดิมมาก่อน) รหัสทั้งหมดต่อไปนี้เป็นรหัสใหม่ทั้งชุด (FR-01 ถึง FR-24, NFR-01 ถึง NFR-08):

- **FR-01 ถึง FR-04**: ข้อมูลทั่วไป/พิกัด GPS/ข้อมูลกายภาพอาคาร/อันตรายสภาพโดยรอบ
- **FR-05 ถึง FR-11**: การประเมินความเสียหายโครงสร้าง (ภายนอก, แยกตามวัสดุ, โครงหลังคา, ส่วนประกอบอาคาร, ระบบไฟฟ้า, สรุปผล 3 สี, การแสดงเกณฑ์อ้างอิงในแอป)
- **FR-12 ถึง FR-15**: ภาพถ่ายและ AI วิเคราะห์รอยร้าว (ถ่ายภาพผูกตำแหน่ง, AI ประเมินความกว้างรอยร้าว, การยืนยันผลโดยผู้สำรวจ (human-in-the-loop), การวาดภาพประกอบ)
- **FR-16 ถึง FR-20**: ผู้สำรวจ การรับรองผล และการมอบหมายงาน (ข้อมูลผู้สำรวจ/หัวหน้าผู้สำรวจ, เวลาสำรวจ, ลายมือชื่อดิจิทัล, การตรวจทาน, การมอบหมายงาน)
- **FR-21 ถึง FR-24**: การจัดการผู้ใช้/สิทธิ์ตามบทบาท, dashboard ภาพรวม, ส่งออกรายงาน, ค้นหา/กรองรายการ
- **NFR-01 ถึง NFR-08**: Availability/Offline Support, Performance/Reliability (sync ภาพขนาดใหญ่), Data Integrity (conflict resolution), Usability/Compatibility (มือถือ/แท็บเล็ต), Auditability, Accuracy, Scalability, Security

### สรุปคำถามที่ถามผู้ใช้และคำตอบที่ได้

ระหว่างงานนี้พบความไม่สอดคล้องสำคัญ: requirement ดิบที่ผู้ใช้พิมพ์มาระบุว่าเป็นเหตุการณ์ "น้ำท่วม" แต่เอกสารต้นทาง PDF ที่มีอยู่ในตอนแรก (`HandBook_CheckEarthQuake.pdf`, `Form_DPT_EarthEquake_Fill_in V1.pdf`) เป็นเรื่อง "แผ่นดินไหว" ล้วน จึงหยุดถามผู้ใช้ก่อนเขียนเอกสาร (ไม่มี AskUserQuestion ในเซสชันนี้ จึงตั้งคำถามผ่านข้อความรายงานกลับ ให้ผู้ประสาน/ผู้ใช้ตอบผ่านช่องทางของตน) คำถาม-คำตอบสรุปได้ดังนี้:

1. **Q1 — ระบบครอบคลุมภัยพิบัติแบบใด**: ผู้ใช้ยืนยันว่าเป็น **"อุทกภัย/น้ำท่วม"** ตามที่พิมพ์มาแต่แรก ไม่ใช่การพิมพ์ผิด และภายหลังผู้ใช้ส่งเอกสารต้นทางเพิ่ม `docs/01-requirements/00-source/Form_DPT_Flood_Survey.pdf` ซึ่งเป็นแบบฟอร์ม DPT ฉบับอุทกภัยตัวจริง ให้ใช้เป็นแหล่งความจริงหลักของโครงสร้างข้อมูล ส่วน PDF แผ่นดินไหว 2 ไฟล์เดิมใช้เป็นเอกสารประกอบ (โดยเฉพาะเกณฑ์ความกว้างรอยแตกร้าวเป็นหน่วยมิลลิเมตร เนื่องจากแบบฟอร์มอุทกภัยอ้างอิงเลขหน้าคู่มือชุดเดียวกัน) ไม่ต้องออกแบบเป็นระบบรองรับหลายภัยพิบัติในตอนนี้
2. **Q2 — ขอบเขตความสามารถ AI**: ผู้ใช้ยืนยันว่าระบบต้องมี AI วิเคราะห์รอยร้าวจากภาพถ่ายเพื่อช่วยวัด/จัดระดับความกว้างรอยแตก โดยต้อง**เสนอผลให้ผู้สำรวจยืนยันเสมอ** (human-in-the-loop ผู้สำรวจตัดสินใจสุดท้าย) → เขียนเป็นกลุ่ม FR-12 ถึง FR-15 แยกชุดของตัวเอง
3. **Q3 — อุปกรณ์และการทำงานออฟไลน์**: ผู้ใช้ยืนยันว่าใช้งานผ่านมือถือ/แท็บเล็ต และต้องรองรับการทำงาน**ออฟไลน์เต็มรูปแบบ** (กรอกครบทุกหมวดโดยไม่มีสัญญาณ แล้ว sync ภายหลัง รวมถึง sync ภาพขนาดใหญ่และจัดการ conflict) → เขียนเป็น NFR-01 ถึง NFR-03 (และ NFR-04 ด้าน mobile) ระดับความสำคัญ **สูง**
4. **Q4 — บทบาทผู้ใช้**: ผู้ใช้ยืนยัน 4 บทบาท: ผู้สำรวจภาคสนาม, หัวหน้าผู้สำรวจ, ผู้ดูแลระบบ, หน่วยงานส่วนกลาง/ผู้บริหาร → สะท้อนในหัวข้อ 3 ของเอกสาร spec และ FR-16 ถึง FR-22

นอกจากนี้ผู้ใช้ระบุว่า footer หน้า 5/5 ของ `Form_DPT_Flood_Survey.pdf` ยังพิมพ์คำว่า "แผ่นดินไหว" ค้างอยู่ (หน้า 1-4 เป็น "อุทกภัย" ถูกต้อง) เป็นข้อผิดพลาดตกค้างในเอกสารต้นฉบับของ DPT เอง ไม่นำมาตีความเป็นข้อกำหนดใดๆ
