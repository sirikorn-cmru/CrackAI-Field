### จุดที่โค้ดบังคับกติกาของเอกสารไว้ในตัว

- **ตัวเลขที่เอกสารสั่งห้ามเดา ถูกทำเป็นพารามิเตอร์บังคับ ไม่มีค่าเริ่มต้น** — จำนวนครั้ง PIN ผิด
  (api-spec 1.3, db-spec §11) และกลยุทธ์ merge อัตโนมัติ (db-spec §11, api-spec §16) ผู้เรียกต้อง
  ส่งค่ามาเองเสมอ ระบบจึงไม่มีทางทำงานด้วยค่าที่เดาขึ้นเองได้
- **การล้าง credential/PIN จาก lockout เข้าถึงได้เฉพาะที่เก็บ session** จึงไม่มีทางลบข้อมูลสำรวจ
  ได้แม้โดยอุบัติเหตุ (NFR-01/NFR-11) มีเทสต์ยืนยัน
- **ข้อความปฏิเสธของ "ผิดบทบาท" กับ "นอกขอบเขต" เหมือนกันทุกตัวอักษร** และ "รหัสผ่านผิด" กับ
  "ไม่มีบัญชีนี้" ก็เช่นกัน (NFR-08) มีเทสต์เทียบข้อความ
- **`related_surveyedbuilding_id` เป็นฟิลด์บังคับของ audit draft** ตาม db-spec §10 ข้อ 9 บังคับให้
  ทุกจุดที่เขียนประวัติตัดสินใจตามกฎอย่างชัดแจ้ง

### สิ่งที่ยังไม่ได้ทำใน Phase 1 (4 จาก 11)

- **T-1-07 ส่วนที่เหลือ** — resumable upload ของ `DamagePhoto`/`Sketch` ติดที่ **ขนาด chunk และ
  เกณฑ์เวลา stale ยังไม่ตัดสินใจ** (db-spec §11, api-spec §16 ระบุ "ห้ามเดาตัวเลข")
- **T-1-08 ส่วนที่เหลือ** — กลยุทธ์ auto-merge จริง ติดที่ยังไม่ตัดสินใจว่าจะ merge บางส่วนก่อน
  หรือส่งให้มนุษย์ทุกครั้ง (db-spec §11) โครงสร้างรองรับแล้ว รอเสียบกลยุทธ์
- **T-1-09 (NFR-04)** และ **T-1-10 (NFR-07)** — ต้องมีแอป React Native จริงและสภาพแวดล้อมรันจริง
  ก่อนจึงวัดผลได้ ยังไม่ได้เริ่ม
- **ชั้นขนส่ง (HTTP/protocol)** — ยังไม่เลือก web framework/protocol ใน [[technology-stack]]
  ชั้น domain จึงเขียนแบบไม่รู้จัก HTTP ไว้ก่อน

### ช่องว่างของเอกสารที่พบระหว่างพัฒนา (ยังไม่แก้ — ไม่ใช่ไฟล์ที่เทรดนี้เป็นเจ้าของ)

1. **api-spec 1.1 ↔ 1.3 ไม่สอดคล้องกัน** — 1.1 สร้าง session ที่ `is_offline_cached = false` เสมอ
   แต่ 1.3 บอกว่าทำงานกับ session ที่ `is_offline_cached = true` และไม่มี operation ใดเปลี่ยนค่านี้
   โค้ดจึงตัดสินจากการมีอยู่ของ `cached_pin_secret` แทน พร้อมหมายเหตุกำกับไว้ในโค้ด
2. **NFR-11 ไม่ปรากฏใน [[release-plan]] และไฟล์ task ทั้ง 4 เฟสเลย** — ทั้งที่เป็นระดับความสำคัญสูง
   และถูก implement ไปแล้วในรอบนี้ ควรรัน `/sync-phase-plan` เพื่อให้ `phase-planner` เพิ่มเข้า Phase 1
3. **ข้อความ "ไม่ผูกกับ tech stack ใดๆ เนื่องจาก `technology-stack.md` ยังไม่มีการตัดสินใจ" กลายเป็นเท็จ**
   ปรากฏใน [[release-plan]] และไฟล์ task ทั้ง 4 ไฟล์ — stack ตัดสินไปแล้วเมื่อ 2026-09-03

## sync-phase-plan — ปิดช่องว่าง NFR-11 และประโยค tech stack เท็จ (`phase-planner`)

ทำตามที่รายงานไว้ในหัวข้อ "ช่องว่างของเอกสารที่พบระหว่างพัฒนา" ด้านบน (ข้อ 2 และ 3)

### ขั้นตอนที่ทำ

1. ตรวจ [[backlog]] และ [[feature-list]] ล่าสุดเทียบกับ [[release-plan]] และไฟล์ task ทั้ง 4 ไฟล์ครบทุกรหัส (44 รหัส) ยืนยันว่า **NFR-11 เป็นรหัสเดียวที่ตกหล่น** ไม่มีรหัสอื่นตกหล่นเพิ่มเติม (FR-01–FR-33 และ NFR-01–NFR-10 ที่เหลือครบถ้วนตรงกันทุกตัว)
2. เสนอ 2 ประเด็นที่ต้องให้ผู้ใช้ตัดสิน (ไม่เดาเอง) กลับไปยัง orchestrator พร้อมทางเลือกและข้อดี/ข้อเสียของแต่ละทาง:
   - **NFR-11 ควรเป็น task ใหม่ (T-1-12) หรือผนวกเข้า T-1-04/T-1-05** — ผู้ใช้เลือก **สร้าง task ใหม่ T-1-12** (ไม่เรียงเลข task เดิมใหม่ เพราะ commit `727241c` อ้างอิง T-1-03/T-1-11 ไว้แล้ว)
   - **ประโยค "ห้ามระบุ tech stack ... ยังไม่มีการตัดสินใจ" ควรแก้เป็นอะไร** — ผู้ใช้เลือก **เปลี่ยนเหตุผลเป็นการแบ่งชั้นเอกสาร** (task ยังคงเขียนเชิงพฤติกรรม/ผลลัพธ์เท่านั้นเหมือนเดิม แต่เหตุผลเปลี่ยนจาก "ยังไม่ตัดสินใจ" เป็น "เป็นชั้นแผนงานระดับความสามารถ ไม่ใช่ชั้นออกแบบเชิงเทคนิค")
3. แก้ไฟล์ตามที่ผู้ใช้ยืนยัน:
   - **[[release-plan]]**: เพิ่ม NFR-11 เข้ารายการรหัสของ Phase 1 (overview, ตารางสรุป, ส่วนรายละเอียด Phase 1, Exit criteria ใหม่เรื่อง PIN lockout ที่ต้องไม่กระทบข้อมูลสำรวจ/คิวรอซิงค์), ปรับจำนวนรหัสรวมจาก 43 → **44 รายการ**, ปรับจำนวนรหัส Phase 1 จาก 11 → **12 รหัส**, เพิ่มบรรทัด "อัปเดต 2026-09-04" อธิบายที่มา, แก้ประโยคเปิด (บรรทัด 5) ให้เหตุผลเป็นการแบ่งชั้นเอกสารแทน "ยังไม่ตัดสินใจ tech stack"
   - **[[phase-1-foundation-auth-offline-tasks]]**: เพิ่มแถว **T-1-12** (NFR-11) — เขียนเชิงพฤติกรรมล้วน ไม่ระบุจำนวนครั้งสูงสุด (คาดว่า 5-10 ครั้งตาม db-spec §10 ข้อ 10/api-spec 1.3 แต่ "ห้ามเดาตัวเลข") ระบุ dep: T-1-04, T-1-05 พร้อมกำกับไว้ชัดว่าเป็น "ประเด็นรอตัดสินใจ" เรื่องตัวเลข และย้ำว่าการล้าง credential ต้องไม่กระทบข้อมูลสำรวจ/คิวรอซิงค์ (NFR-01) ปรับสรุปท้ายไฟล์จาก 11 → **12 tasks**, แก้ประโยคเปิด (บรรทัด 5) เช่นเดียวกับ release-plan
   - **phase-2/3/4 tasks.md ทั้ง 3 ไฟล์**: แก้เฉพาะประโยคเปิด (บรรทัด 5) ให้เหตุผลเป็นการแบ่งชั้นเอกสาร โดยคงข้อความส่วนที่เหลือของบรรทัด (คำอธิบาย dependency ข้าม phase ของแต่ละไฟล์) ไว้ครบทุกไฟล์ ไม่มีเนื้อหาอื่นเปลี่ยนแปลง
