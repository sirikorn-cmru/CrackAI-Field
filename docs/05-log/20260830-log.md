### การตรวจสอบตัวเองก่อนจบงาน
- อ่าน `login.html`, `dashboard.html` กลับทั้งไฟล์หลังแก้: โครงสร้างแท็กปิดครบ, ไม่มี syntax error ที่เห็นได้, `id` ของ mock input (`d-username`/`d-password`) ไม่ชนกับ `id` ของฟอร์มจริง (`username`/`password`)
- อ่าน `prototype.md` ส่วนที่แก้กลับ: ไม่ขัดแย้งกับตารางไฟล์ ↔ FR เดิม (ไม่มีการเปลี่ยนรหัส FR ที่ครอบคลุมต่อไฟล์)
- ยืนยัน `api-spec.md` มี operation "2.4 เปิดใช้งานบัญชีผู้ใช้คืน" จริงก่อนแก้ `prototype.md` (grep ตรงกับที่ผู้เรียกระบุ)
- เรียก Skill `dataviz` ก่อนแก้ `dashboard.html` (มีกราฟ) ตามข้อบังคับ — ยืนยันว่าการใช้ `.empty-state` แบบ block แยกต่างหาก (ไม่ใช่ inline ในแถว stacked-bar) เหมาะสมกว่า เพราะไม่ต้องปรับขนาด/ตำแหน่งของคลาสเดิม และไม่ทำให้แท่งกราฟที่มีค่า 0 ถูกเข้าใจผิดว่าเป็นข้อมูลจริง
- **ยังไม่ได้เปิดดูด้วยเบราว์เซอร์จริง** — ตรวจได้เฉพาะจากการอ่านไฟล์กลับเท่านั้น

### การตรวจสอบตัวเองก่อนจบงาน
- อ่านไฟล์ใหม่ทั้ง 4 ไฟล์และไฟล์ที่แก้ทั้งหมดกลับ: แท็กปิดครบ, `href`/`<option value>` ทุกจุดตรงกับชื่อไฟล์จริงที่สร้าง (ไม่มีลิงก์ตาย), ทุกไฟล์อ้างอิง `<link rel="stylesheet" href="style.css">` ถูกต้อง, ไม่มี class ใหม่ที่ไม่มีอยู่ใน `style.css` เดิม (ตรวจกับสำเนา `style.css` เต็มที่อ่านไว้ตอนต้น) ยกเว้น `<style>` inline เฉพาะไฟล์สำหรับ toggle demo (`.path-panel`, `.role-panel`, `.result-panel`) ซึ่งเป็นรูปแบบเดียวกับที่ `login.html`/`field-survey-photo-ai.html` ใช้อยู่แล้ว ไม่ใช่ token ใหม่
- เทียบไฟล์จริงกับตารางที่อัปเดตใน `prototype.md`: ตรงกันครบ 17/17 ไฟล์ HTML + 1 stylesheet ไม่มีไฟล์ตกหล่น/เกินมาโดยไม่ได้แจ้ง
- **ยังไม่ได้เปิดดูด้วยเบราว์เซอร์จริง** — ตรวจได้เฉพาะจากการอ่านไฟล์กลับเท่านั้น เป็น follow-up ที่ควรทำในเทรดหลัก
