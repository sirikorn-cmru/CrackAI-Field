รับสัญญาณ `## NEEDS_DESIGN_SYSTEM` จาก `/audit-prototype` รอบก่อนหน้า (ดู entry ด้านบน): token `--state-pending-*`/`--state-synced-*` ซึ่ง `DESIGN.md` หัวข้อ 2.4 นิยามไว้เฉพาะ "สถานะการซิงค์ข้อมูล" (NFR-01/02) ถูก `lead-assign.html`, `field-my-tasks.html` (ผ่าน class `.badge.pending`/`.badge.synced`, `.sync-indicator.*`) และ `lead-review-list.html` นำไปใช้สื่อความหมาย "สถานะความคืบหน้าของงาน/การตรวจทาน" (FR-19/20) และ `.wizard-step.done` ในหน้าจอวิซาร์ดสำรวจ 4 หน้านำไปใช้สื่อ "ขั้นตอนที่ทำเสร็จแล้ว" — เป็น semantic drift ที่ไม่ใช่ข้อผิดพลาดของ prototype แต่เป็นช่องว่างของ design system งานนี้**แก้เฉพาะ `DESIGN.md`** ไม่แตะไฟล์ prototype ตามหน้าที่เจ้าของไฟล์

**หมายเหตุข้อจำกัดเซสชัน**: เซสชันนี้ไม่มีเครื่องมือ `AskUserQuestion` ให้ใช้งาน (ไม่อยู่ในชุดเครื่องมือที่ได้รับ) จึงไม่ได้สัมภาษณ์ผู้ใช้ตามขั้นตอนปกติของ `design-system-writer` — เลือกแนวทางที่เห็นว่าเหมาะสมที่สุดเองพร้อมเหตุผลกำกับ ให้ผู้เรียกใช้ (agent ที่เรียกงานนี้) นำไปยืนยันกับผู้ใช้จริงแทน

### แนวทางที่พิจารณาและเหตุผลที่เลือก
พิจารณา 3 แนวทาง:
1. **เพิ่มกลุ่ม token ใหม่ `--state-progress-*` แยกจากสถานะซิงค์โดยสิ้นเชิง (เลือกแนวทางนี้)** — ข้อดี: ตัดการเชื่อมโยงเชิงความหมายระหว่าง "สถานะซิงค์" กับ "สถานะความคืบหน้าของงาน" อย่างถาวร ป้องกันปัญหาที่ระบุไว้ในสัญญาณต้นทาง (เปลี่ยนสีสถานะซิงค์แล้วสีสถานะงานเปลี่ยนตามโดยไม่ตั้งใจ) และตรงกับหลักการที่ `DESIGN.md` ใช้อยู่แล้วกับ conflict/ai token (แยก token ตามความหมายแม้จะมีสถานะ "ไม่เสร็จ/เสร็จแล้ว" คล้ายกัน) ข้อเสีย: เพิ่มจำนวน token ในเอกสาร ต้องระวังไม่ให้ผู้ใช้สับสนว่าทำไมสีซ้ำกับกลุ่มเดิม (แก้ด้วยหมายเหตุกำกับชัดเจนในเอกสาร)
2. ขยายนิยาม token เดิมให้ครอบคลุมทั้งสองความหมาย — ไม่เลือก เพราะเป็นสาเหตุของปัญหาเดิม (ทำให้ token เดียวรับผิดชอบสองโดเมนที่ไม่เกี่ยวข้องกัน สถานะซิงค์คือ NFR-01/02 ส่วนสถานะความคืบหน้างานคือ FR-19/20 การเปลี่ยนแปลงในโดเมนหนึ่งจะกระทบอีกโดเมนเสมอ)
3. คงนิยามเดิม ผลักให้ `build-prototype` แก้การใช้งานผิดแทน — ไม่เลือก เพราะ prototype มีความต้องการใช้สีสถานะ "ยังไม่เสร็จ/เสร็จแล้ว" จริงตาม FR-19/20 การไม่ให้ token รองรับความหมายนี้เลยจะทำให้ prototype ไม่มีทางเลือกอื่นนอกจากยืมของกลุ่มอื่นซ้ำอีก (ปัญหาเดิมจะเกิดซ้ำกับ token กลุ่มอื่นแทน)

**การตัดสินใจเรื่องค่าสี**: ให้ `--state-progress-todo-*` ใช้ค่าเดียวกับ `--state-pending-*` (`#5C5346`/`#EFEBE4`) และ `--state-progress-done-*` ใช้ค่าเดียวกับ `--state-synced-*` (`#41564A`/`#E9EEEA`) ทุกตัวอักษร — จงใจให้ค่าซ้ำเพื่อไม่ต้องคำนวณคอนทราสต์ใหม่ (ค่านี้ผ่าน AAA ≥7:1 ตามที่ยืนยันไว้แล้วในหัวข้อ 2.3 ของเอกสาร) แต่แยกชื่อ token เพื่อตัดการเชื่อมโยงเชิงความหมาย บันทึกไว้ชัดเจนในหัวข้อ "สิ่งที่ยังไม่ตัดสินใจ" ว่าถ้าในอนาคตพบเคสจริงที่สถานะซิงค์และสถานะความคืบหน้าของงานปรากฏพร้อมกันในหน้าเดียวจนผู้ใช้แยกไม่ออก ต้องกลับมาแยกค่าสีให้ต่างกันจริง

### ส่วนที่แก้ใน `docs/02-design/DESIGN.md`
1. **หัวข้อ 2.4** — เพิ่มคำเตือนชัดเจนว่า `--state-pending-*`/`--state-synced-*` ใช้ได้เฉพาะสถานะซิงค์ (NFR-01/02) เท่านั้น และเพิ่มตารางใหม่ "สถานะความคืบหน้าของงาน/การตรวจทาน" พร้อม token `--state-progress-todo-fg/-bg` และ `--state-progress-done-fg/-bg` ระบุ FR-19/20 กำกับ พร้อมหมายเหตุอธิบายเหตุผลที่ค่าสีซ้ำกับกลุ่มเดิม
2. **หัวข้อ 3.8 (ป้ายสถานะ)** — เพิ่มตารางช่วยตัดสินใจ "ป้ายนี้สื่อเรื่องอะไร → ใช้ token กลุ่มใด" ครอบคลุมทั้ง 5 กลุ่ม (severity, sync, conflict, ai, progress) พร้อมตัวอย่างหน้าจอจริงที่เกี่ยวข้อง เพื่อป้องกัน semantic drift ซ้ำในอนาคต
3. **หัวข้อ 4 (UX Guidelines)** — เพิ่ม `UX-14 แยก token ตามความหมาย ห้ามข้ามกลุ่มความหมาย` เป็นกติกาบังคับใหม่
4. **หัวข้อ 5 (สิ่งที่ยังไม่ตัดสินใจ)** — เพิ่มบันทึกว่าค่าสีของ `--state-progress-*` ซ้ำกับ `--state-pending-*`/`--state-synced-*` โดยตั้งใจ และเงื่อนไขที่ต้องกลับมาแยกค่าสีจริงในอนาคต

### คู่สีที่ต้องคำนวณคอนทราสต์ยืนยันเพิ่มเติม
**ไม่มี** — ค่าสีของ `--state-progress-todo-*`/`--state-progress-done-*` เป็นค่าเดียวกับ `--state-pending-*`/`--state-synced-*` ที่มีอยู่แล้วในเอกสาร (ระบุไว้ว่าผ่าน AAA ≥7:1 ทั้งบนพื้น `--surface-page` และบนพื้น `-bg` ของตัวเองแล้วในหัวข้อ 2.3) จึงไม่มีค่าสีใหม่ที่ต้องคำนวณซ้ำ — คงยึดกติกาเดิมว่าไม่มีการอ้างตัวเลขคอนทราสต์ที่ไม่ได้ตรวจสอบ

### ผลกระทบต่อ Prototype
มี — `lead-assign.html`, `field-my-tasks.html`, `lead-review-list.html` และหน้าจอวิซาร์ดสำรวจ 4 หน้าที่ใช้ `.wizard-step.done` **ยังใช้ token `--state-pending-*`/`--state-synced-*` เดิมอยู่** ต้องเปลี่ยนไปอ้างอิง `--state-progress-todo-*`/`--state-progress-done-*` แทน เพื่อให้สอดคล้องกับนิยามใหม่ — งานนี้ไม่ได้แก้ไฟล์ prototype (นอกเหนือขอบเขตหน้าที่) จึงต้องส่งต่อให้ `/build-prototype` หรือ `prototype-writer` ดำเนินการแก้ไขในรอบถัดไป

### สิ่งที่ยังไม่ตัดสินใจ (เพิ่มจากรอบนี้)
- ถ้าสถานะซิงค์และสถานะความคืบหน้าของงานต้องแสดงพร้อมกันในหน้าเดียวจนแยกไม่ออก ต้องแยกค่าสีจริงในรอบถัดไป (ยังไม่มีเคสยืนยัน)
- ทุกรายการเดิมในหัวข้อ 5 ของ `DESIGN.md` (ไอคอน, high-visibility mode, dark mode, โลโก้, ค่าเชิงเทคนิค) ยังคงค้างอยู่เหมือนเดิม ไม่มีการเปลี่ยนแปลงในรอบนี้
